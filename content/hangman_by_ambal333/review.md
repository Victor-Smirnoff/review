# Ревью проекта [hangman](https://github.com/ambal333/hangman)



## Плюсы:

+ Корректность игровой логики. Основной сценарий работает: буквы открываются верно, ошибки считаются, виселица рисуется по
стадиям, победа/поражение и повтор игры отрабатывают. 

+ Понятное разделение на пакеты: логика игры, получение слова, отрисовка.

+ Код короткий и читаемый, легко разобраться новичку.

+ Отрисовка виселицы реализована честно по стадиям, ASCII-арт читаемый.

+ Корректно указана кодировка `utf-8` при чтении файла, используется `pathlib`.

+ Нормализация регистра (`word.upper()`, ввод `.upper()`) исключает ошибки регистра; поддержан `Ё`.


## Минусы:

- Критично: пустой ввод = мгновенная победа.
Если просто нажать Enter вместо ввода буквы, то игра завершается победой, проблема логики обработки входных данных.
Игра объявляет победу, хотя ни одна буква не угадана.
Решение: Проверку победы надо делать только после валидного хода и через сравнение множеств, а не через `letters`.

- Критично: при отсутствии файла слов игра ломается молча.
Вообще и сам файл со словами "russian_words" не имеет расширения, что не очень хорошо.
Функция `random_word` делает `random.choice(list_words)`. 
На строке `random.choice` вернёт случайный символ строки "файла не существует", и игра начнёт загадывать одну букву. 
Плюс путь относительный `Path("./words/russian_words")`, поэтому при запуске не из корня проекта файл не находится, 
и вместо ошибки получаем случайную букву.
Здесь зашита ещё одна проблема с `except FileNotFoundError:` - перехват ошибки и спрятывание её. 
Это антипаттерн. Если ошибки таким образом прятать, то их потом очень тяжело отловить.
Решение: возвращать список в любом случае или пробрасывать исключение;

- Функция `def get_random_word(self)` принимет параметр `self`, но нигде его не использует.
Вместо получения списка со словами, она сама вызывает фунцию чтения файла, и потом выбирает то, что ей вернули.
Тоже самое функция `def random_word(self):` принимет параметр `self`, но нигде его не использует. Они дублируют друг друга.

- Нет обработки пустого списка слов.
Если `words/russian_words` пуст, `random.choice([])` бросит `IndexError`.
Стоит проверять непустоту и/или перечитывать файл один раз при старте.

- Проверка конца игры выполняется на каждой итерации.
Строка ` if "*" not in letters or self.fault == 7:` стоит вне блока валидации, поэтому срабатывает даже после невалидного/пустого ввода. 
Логически её место сразу после обработки корректной буквы.

- Многосимвольный ввод проходит проверку по подстроке.
`user_letter in russian_letter` для строки длиной > 1 - это проверка подстроки.
Например, `"АШ"` есть в алфавитной строке (`МАШИНА`), поэтому такой ввод пройдёт валидацию. 
Нужно явно требовать `len(user_letter) == 1`.

- Состояние виселицы `attempt == 0` не используется.
`draw_gallows` содержит ветку для `attempt == 0`, но первый вызов всегда при `fault == 1`. 
Начальное состояние не рисуется - виселица появляется только после первой ошибки. 
Ветка мёртвая либо логика отрисовки неполная.

- Фунция `def draw_gallows(attempt)` имеет множество `if-elif` конструкций. 
Это почти всегда реф флаг, что в логике что-то не так.
Можно сделать список или словарь с рисунками, и возвращать из этой коллекции значения по ключу или индексу.
Никаких `if-elif` не надо.

- Магическое число `7` продублировано в нескольких местах.
Лучше вынести в константу `MAX_FAULTS`. `self.fault == 7` надёжнее заменить на `>=`, чтобы не зависеть от инкремента.

- Стиль кода. Плохие отсутпы, импорты слиты без отступа, присутствуют не валидные f-строки `f"файла не существует"`

- Нет аннотаций типов и docstring'ов (но на первом проекте можно и без них).


## Итог:

Проект рабочий в позитивном использовании сценария: базовый игровой цикл, отрисовка и
перезапуск реализованы верно. Но есть два серьёзных дефекта, ломающих игру:
мгновенная победа по пустому вводу и некорректная обработка отсутствующего файла
слов (плюс хрупкий относительный путь). 
Также игровая логика перегружена вложенными циклами и магическими числами, присутствует мёртвый код.
