Ревью проекта [hangman](https://github.com/Mirzopulod/hangman)


Плюсы:

+ Проект запускается и работает.

+ Есть валидация введенных символов (только одна русская буква), повторно введённая буква не расходует попытку.

+ Используется только стандартная библиотека, внешних зависимостей нет - проект легко запустить.

+ Логика разделена на небольшие функции с понятными названиями (`get_random_word`, `validate_letter`, `play_round`, `show_hangman`).

+ Обрабатываются отсутствующий и пустой словарь.

+ README подробно описывает возможности, запуск, управление и структуру проекта.


Минусы:

- Отсутсвует аннотации типов в аргументах функций. 
Старайся с самого начала привыкать указывать какие типы данных в аргументах передаются.
Это повышает читаемость кода, в IDE появляются подсказки с типами, можно проводить статический анализ кода.
Примеры:
`def validate_letter(letter)` -> `def validate_letter(letter: str)`
`def show_hangman(errors):` -> `def show_hangman(errors: int):`

- Нет проверки на введение русской буквы верхнего регистра (это тоже валидный ввод).
Здесь просто добавить метод `lower()` в проверку.

- Переменная `alphabet` используется более 1 раза в разных функциях, это дублирование, значит её надо вынести в общую переменную/константу `ALPHABET` уровня модуля.
Её же лучше сделать не строкой, а множеством, тогда поиск будет O(1), а не O(N).
Здесь же при использовании этой переменной возникают ошибки с регистром символов в словах: если в файле будет слово `Арбуз`, то оно будет отброшено, 
так как переменная содержит только символы в нижнем регистре

- `get_random_word` работает неэффективно - проверка каждого символа в слове - это медленно. 
Вместо цикла можно использовать функцию `all()` для проверки что все символы слова есть в `alphabet`.

- Цикл проверки символов можно упростить. 
Вместо ручного цикла с флагом `is_russian` можно использовать `all(ch in ALPHABET for ch in word)`. 

- Функция `get_random_word` смешивает слишком много обязанностей: читает файл, печатает ошибки, фильтрует слова, выбирает случайное слово и возвращает `None` как признак ошибки. 
Логичнее разделить загрузку (`load_words`) и выбор (`pick_word`), а ошибки обрабатывать в `main`. Это упростит тестирование.

- Метод `words = f.read().splitlines()` читает файл полностью.
Можно сделать тоже самое, но построчно: `words = [line.strip().lower() for line in f]`

- В функции `def validate_letter(letter)` лучше не крутить цикл и проверки на корректность ввода, а просто возвращать `bool` на введенный символ.

- Отрисовка виселицы отстаёт на одну ошибку. 
В `play_round` вызов `show_hangman(errors)` стоит до `errors += 1`. 
Поэтому после первой неверной буквы показывается ещё пустая виселица, после пятой - кадр с двумя руками, 
после шестой - кадр с одной ногой, и только после выхода из цикла рисуется полный кадр. 
На проигрыше подряд выводятся два кадра: неполный и полный.
Исправление: сначала обновить `errors`, затем вызвать `show_hangman(errors)`, а финальный кадр не рисовать повторно.

- Магическое число 6. 
Количество попыток зашито в строках 132, 162 и 168 и не связано с `len(HANGMAN) - 1`. 
Если добавить или убрать кадр, легко получить несоответствие. Нужна константа вроде `MAX_ERRORS = len(HANGMAN) - 1`.
Здесь же желательно помнить про возможный `keyerror` если мы обратимся к несуществующему индексу переменной `HANGMAN`.


Итог:

Проект рабочий и для учебного уровня выглядит аккуратно: логика разбита на небольшие функции, есть меню, проверка ввода, защита от повторного ввода и обработка проблем со словарём. 
Главные направления роста - это детали: типизация, регистр символов, вынос общих констант, отставание отрисовки, смешивание ответственности функций.
